# Plots and images in Shiny for R

## Overview

Pair `renderPlot()` with `plotOutput()` to turn base, lattice, or ggplot2
code into a reactive output — Shiny captures the drawing commands and serves
a PNG. Enable `click=`/`hover=`/`brush=` on `plotOutput()` to get mouse
coordinates as `input$<id>_<event>`, then use `nearPoints()`/
`brushedPoints()` to turn coordinates into selected rows instead of computing
hit-testing yourself. The anti-pattern this reference prevents is rebuilding
an expensive plot on every input change — reach for `renderCachedPlot()` (or
`bindCache()`) so identical inputs are served from cache, not re-executed.

## Render a plot: renderPlot() / plotOutput()

`renderPlot(expr)` accepts any code that draws to the current graphics
device — base `plot()`, lattice, or a returned ggplot2 object. Pair it with a
`plotOutput(outputId)` placeholder (see the full app below for a minimal
pair). Set display size on `plotOutput(width=, height=)` (CSS units);
`renderPlot()` also accepts `width=`/`height=` (pixels, or a reactive
function) to force an R-side pixel size instead of the browser-controlled
`"auto"`. With ggplot2, **return** the ggplot object rather than
`print()`-ing it, or click/brush coordinate scaling breaks. `alt=` sets
screen-reader text; left `NA` (the default), Shiny extracts it from
`ggplot2::get_alt_text()` when possible.

## Read plot interactions: click, dblclick, hover, brush

Pass a string (or an options object from `clickOpts()`, `hoverOpts()`,
`brushOpts()`) to `plotOutput()`'s `click=`, `dblclick=`, `hover=`, `brush=`
arguments. Each enabled event populates a reactive `input$<id>_<event>` with
mouse coordinates, scaled to data space for base graphics and ggplot2:
`_brush` gives `xmin`/`xmax`/`ymin`/`ymax`; `_click`/`_dblclick`/`_hover` give
`x`/`y`. Multiple `plotOutput()` calls can share a brush `id` so brushing one
clears the others.

## Map interactions to data rows: nearPoints() / brushedPoints()

`nearPoints(df, coordinfo, xvar = NULL, yvar = NULL, panelvar1 = NULL,
panelvar2 = NULL, threshold = 5, maxpoints = NULL, addDist = FALSE, allRows =
FALSE)` returns rows near a click/hover/dblclick event, sorted by distance;
`brushedPoints(df, brush, xvar = NULL, yvar = NULL, panelvar1 = NULL,
panelvar2 = NULL, allRows = FALSE)` returns rows under a brush. Note the two
`panelvar*` arguments sitting before `threshold`/`allRows` — name anything
past `yvar` rather than passing it positionally. Both take an
`input$<id>_*` value as `coordinfo`/`brush`. ggplot2 plots usually infer
`xvar`/`yvar` automatically; base graphics need them supplied. `allRows =
TRUE` returns every row with a `selected_` boolean column instead of
filtering. See the full app below for both wired to a brushed scatter plot.

## Cache expensive plots: renderCachedPlot() / bindCache()

`renderCachedPlot(expr, cacheKeyExpr, sizePolicy = , res = , cache = "app")`
re-executes `expr` only when `cacheKeyExpr` changes, retrieving a stored PNG
otherwise — a shortcut for `renderPlot(expr) |> bindCache(...)`. Build the
key from the same reactive inputs the plot depends on, since the key (not
`expr`) controls re-execution. `cache = "app"` shares cached plots across
all sessions; `cache = "session"` scopes caching to one user.

```r
# Partial snippet: plugs into a server function

output$plot <- renderCachedPlot(
  {
    Sys.sleep(1) # pretend this plot is expensive
    seqn <- seq_len(input$n)
    plot(mtcars$wt[seqn], mtcars$mpg[seqn])
  },
  cacheKeyExpr = input$n
)
```

## Serve a static image: renderImage()

`renderImage(expr, deleteFile)` returns a list with at least `src` (a file
path) for output not generated by plotting code — a pre-rendered file, or a
temp file you wrote yourself. Pair it with `imageOutput()`. Set
`deleteFile = TRUE` for a temp file created inside `expr`; use
`deleteFile = FALSE` for a persistent asset shipped with the app.

```r
# Partial snippet: plugs into a server function

output$snapshot <- renderImage({
  outfile <- tempfile(fileext = ".png")
  png(outfile, width = 400, height = 300)
  hist(rnorm(200))
  dev.off()
  list(src = outfile, width = 400, height = 300, alt = "Histogram")
}, deleteFile = TRUE)
```

## ggplot2 ecosystem pointers

- {thematic} (`thematic::thematic_shiny()`) auto-themes base/ggplot2/lattice
  plots to match the app's bslib theme.
- {plotly} (`plotly::ggplotly()`) adds pan/zoom/tooltip interactivity to a
  ggplot object.

## Full app: scatter plot with brush selection

```r
library(shiny)

ui <- fluidPage(
  plotOutput("scatter", brush = brushOpts(id = "scatter_brush")),
  tableOutput("selected")
)

server <- function(input, output, session) {
  output$scatter <- renderPlot({
    plot(mtcars$wt, mtcars$mpg, xlab = "wt", ylab = "mpg")
  })

  output$selected <- renderTable({
    brushedPoints(mtcars, input$scatter_brush, xvar = "wt", yvar = "mpg")
  })
}

shinyApp(ui, server)
```

## Quick reference

| Function | Purpose |
|---|---|
| `renderPlot()` / `plotOutput()` | Draw a reactive plot |
| `renderImage()` / `imageOutput()` | Serve a static or generated image file |
| `nearPoints(df, coordinfo, xvar = , yvar = , ...)` | Rows near a click/hover event |
| `brushedPoints(df, brush, xvar = , yvar = , ...)` | Rows under a brush |
| `renderCachedPlot(expr, cacheKeyExpr)` | Cache plot output on a cheap key |
| `bindCache()` | Add caching to any `render*()`/`reactive()` |
| `clickOpts()`, `hoverOpts()`, `brushOpts()` | Tune interaction behavior |

## Common mistakes

- **Recomputing an expensive plot every tick.** Use `renderCachedPlot()` or
  `bindCache()`.
- **`input$<id>_brush` always `NULL`.** Pass `click=`/`brush=` to
  `plotOutput()`, not `renderPlot()`.
- **`nearPoints()`/`brushedPoints()` erroring on missing `xvar`/`yvar`.**
  Only ggplot2 infers axis columns; supply them for base graphics.
- **Printing a ggplot object instead of returning it.** `print(p)` breaks
  click/brush scaling — return `p` from `renderPlot()`.
- **`renderCachedPlot()` going stale.** `cacheKeyExpr`, not `expr`, controls
  re-execution; every reactive the plot reads must appear in the key.
- **Managing a temp image's lifecycle by hand.** `renderImage(deleteFile =
  TRUE)` already cleans it up after sending.
