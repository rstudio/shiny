# Documentation Style

## Roxygen2 conventions

`DESCRIPTION` sets `Roxygen: list(markdown = TRUE)` and
`Config/roxygen2/version`. Every file in `man/` is generated (first line
`% Generated by roxygen2: do not edit by hand`), and `updateReexports.R`
fails if any is not. Edit the `#'` comments in `R/`, never `man/` or
`NAMESPACE`.

Tags in use across `R/`:

- `@export`: every public function. `@noRd` is for internal
  helpers that carry roxygen comments but no Rd.
- `@rdname`: groups related functions on one page, e.g.
  `@rdname stacktrace`, `@rdname shiny.appobj`, `@rdname updateSelectInput`.
  `@describeIn` is used less often.
- `@inheritParams`: reuses parameter docs instead of copying them.
- `@keywords internal`: exported but hidden from the reference index
  (see checkPkgdown below). `@family` is used for `input elements` and
  `layout functions`.
- `@seealso` and `@return` are common. `@section` is used for long-form
  subsections.
- Markdown links (`[column()]`) are the norm in new docs. Older docs and the
  templates still use Rd markup (`\code{\link{numericInput}()}`); both
  render.

### Templates (`man-roxygen/`)

`man-roxygen/` is `.Rbuildignore`d and holds three templates:

- `update-input.R`: shared `@details`, `session`, `inputId`, and `label`
  docs for the `update*Input()` functions in `R/update-input.R`
  (`@template update-input`).
- `param-env.R` and `param-quoted.R`: `env`/`quoted` param docs taking
  `@templateVar x`, `env`, `quoted` (used in `R/reactives.R` and
  `R/shinywrappers.R`). Both carry the note "Also update observeEvent param
  descriptions!" (roxygen2 issue #1241).

### Examples

Most examples start an app, so they must not run under `R CMD check`. The
dominant pattern is:

```r
#' @examples
#' ## Only run examples in interactive R sessions
#' if (interactive()) {
#'
#' ui <- fluidPage(...)
#' shinyApp(ui, server = function(input, output) {})
#' }
```

Most older example blocks use this `## Only run ... in interactive ... sessions`
comment plus `if (interactive()) {`, with small wording differences. Newer
code uses `@examplesIf` instead: `@examplesIf rlang::is_interactive()`
(`R/busy-indicators.R`), with an extra `rlang::is_installed("mirai")`
condition in `R/extended-task.R`, and `@examplesIf interactive()` in
`R/shiny.R`. Some blocks use `\dontrun{`. For new code, prefer
`@examplesIf`, and add an `is_installed()` guard for Suggests packages.

## Regenerating docs

```bash
Rscript -e 'devtools::document()'   # man/, NAMESPACE, and the Collate: field
```

`DESCRIPTION` has an explicit `Collate:` field, so a new `R/` file is only
loaded after `document()` adds it.

`tools/documentation/checkDocsCurrent.sh` is the CI gate, called from
`.github/shiny-workflows/routine.sh` during the `routine` job:

1. Runs `devtools::document(roclets = c('rd', 'collate', 'namespace'))` and
   fails if `git status --porcelain` is non-empty.
2. Runs `tools/documentation/updateReexports.R`, then
   `tools/documentation/checkPkgdown.R`, and fails again if the tree is
   dirty.

## pkgdown reference index

There is no root `_pkgdown.yml`. The `website` CI job builds a pkgdown site
with pkgdown's default config (see `memory-bank/testing.md`), and it does
not read `tools/documentation/pkgdown.yml`. rstudio/shiny-dev-center uses it to
generate the reference index for shiny.posit.co. Sections include UI Layout,
UI Inputs, UI Outputs, Rendering functions, Reactive programming, Modules,
Testing, OpenTelemetry, Superseded, and a final `internal` section that
pkgdown drops.

`tools/documentation/checkPkgdown.R` (run by `tests/testthat/test-pkgdown.R`
from source trees, and by `checkDocsCurrent.sh`) compares **Rd topic names**
(`man/*.Rd` file names) with the `contents:` entries:

- Every Rd topic must be listed, unless its Rd has `\keyword{internal}` or
  `\docType{package}`. Failure: "Functions missing from
  ./tools/documentation/pkgdown.yml".
- Every listed entry must be an Rd topic or a reexport file from
  `reexports.json`. Failure: "Unrecognized functions in ...".

It checks topics, not exports. A function documented with `@rdname` under
another topic (for example `localOtelCollect` in `withOtelCollect.Rd`) needs
no entry of its own.

When adding an exported function with its own Rd, add it to the right
section of `pkgdown.yml` in the same PR, or mark it `@keywords internal`.

## Reexports (`reexports.json`, `updateReexports.R`)

shiny re-exports functions from htmltools (`tagList`, `HTML`, `tags`,
`singleton`, `validateCssUnit`, ...) and fastmap (`key_missing`).
`tools/documentation/reexports.json` lists the upstream Rd **files** per
package, with an optional `ignore` alias.

`source("tools/documentation/updateReexports.R")` (from the repo root):

- Reads each upstream `man/<file>` at the package's **latest GitHub tag**.
- Regenerates `R/reexports.R` (header: "Generated by ... do not edit by
  hand") with `@importFrom pkg fn` / `@export` / `pkg::fn` blocks.
- Runs `devtools::document()`, and calls `stop()` if `NAMESPACE` changed.
  The message suggests an `Imports:` minimum version to add to
  `DESCRIPTION`.
- Verifies every `man/` file is roxygen-generated.

## NEWS.md entries

User-facing changes get a bullet under the top `# shiny (development
version)` heading. `.github/CONTRIBUTING.md` also asks for this. The dev
section is a flat list of `* ` bullets with a blank line between them.
Released sections use subheadings (`## New features`, `## Improvements`,
`## Bug fixes` or `## Bug fixes and minor improvements`, sometimes
`## Breaking changes`); those are sorted in at release time.

Bullet style:

- Wrap function names in backticks with parens (`` `dateInput()` ``) and
  packages in braces (`` `{watcher}` ``).
- Bug fixes lead with the issue: `* Fixed #1234, #5678: \`dateInput()\`'s
  ...`. Explain the user-visible symptom, then (briefly) the cause or fix.
- End with the PR number in parens: `(#1234)`. Use several when relevant
  (`(#1234, #1235)`). Thank outside contributors inline:
  `(thanks @username, #1234)`.
- Write in plain or present tense ("now works", "is now printed").
  Hard-wrapped and single-line bullets both appear.

## Pitfalls

- **`checkDocsCurrent.sh` fails on any dirty tree.** It uses
  `git status --porcelain`, which includes untracked files. Locally, commit
  or remove stray files first, or the "docs out of date" failure is
  misleading.
- **`updateReexports.R` needs the network and tracks upstream tags.** A new
  htmltools or fastmap release that adds an alias changes `R/reexports.R`
  and `NAMESPACE`. The `routine` job then fails on unrelated PRs until
  someone regenerates and commits.
- **`test-pkgdown.R` only runs from a source checkout.** It sources
  `../../tools/documentation/checkPkgdown.R`, which is absent under
  `R CMD check` (`tools/` is `.Rbuildignore`d), so it skips there. CI still
  runs the check: `checkDocsCurrent.sh` (from `routine`) runs
  `checkPkgdown.R` directly. Locally, use `devtools::test(filter = "pkgdown")`.
- **Edit param docs in `man-roxygen/`, not in `man/`.** Changing
  `env`/`quoted` wording in one function's roxygen will not reach the
  others that use the template.
